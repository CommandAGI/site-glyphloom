The renderer, for agents and developers

The studio is one module, glyphloom.js, with no dependencies. It takes RGBA pixels and returns a grid of characters with their colours, and it writes each export. It runs in a browser and in Node, so an agent can use it without the page. Its source and its tests are in the repository CommandAGI/site-glyphloom.

One function

import { render, toText, toAnsi, toHtml, toAnimatedHtml } from "./glyphloom.js";

// image: { width, height, data } with RGBA bytes (a browser's ImageData has this shape)
const grid = render(image, {
  columns: 80,              // the width in characters
  charAspect: 0.5,          // a cell's width over its height
  charset: "detailed",      // simple | detailed | blocks | braille | binary | custom (with custom: " .oO@")
  dither: "floyd-steinberg",// none | floyd-steinberg | atkinson | ordered
  color: "ansi256",         // none | ansi16 | ansi256 | truecolor
  paper: "dark",            // dark: light ink; light: dark ink
});

process.stdout.write(toAnsi(grid));   // a terminal
toText(grid);                         // plain text
toHtml(grid, { title: "A frame" });   // one self-contained HTML file
toAnimatedHtml(frames, { fps: 10 });  // moving art: one HTML file that plays the grids by CSS, no script

In a browser, paint(ctx, grid) draws the art on a canvas, which the studio saves as a PNG.

Options

optionvalueswhat it does
columns1 and upthe width in characters; the rows follow the image and charAspect
charsetsimple, detailed, blocks, braille, binary, customa ramp from the least ink to the most; braille draws 2×4 dots a cell
dithernone, floyd-steinberg, atkinson, orderedspreads each cell's rounding error to its neighbours, or uses a 4×4 threshold pattern
brightness, contrast, gamma, invertnumbers, a booleantone before the characters are chosen
color, colorTargetnone, ansi16, ansi256, truecolor; fg or bgeach cell's mean colour, on the character or behind it
scanlines, bloom, halftone0 (off) to 1post effects over the art in the HTML exports and the PNG; the characters stay as they are

With a CommandAGI agent

An agent on CommandAGI turns what it sees into text it can read and post with one call of the tool character_art on a CommandAGI host. It takes an image file (PNG, JPEG, WebP or GIF), a camera stream's frame (its video.mjpeg, or the stream folder that request_frame answers with; the last frame, or the one at a second you name) or a 3D model (an STL, an OBJ, or a 3D document in code, which the 3D kernel tessellates, seen from a view you name). It answers with text, ANSI for a terminal, or an HTML file. It only reads.

character_art { "path": "camera/stream", "columns": 80 }
character_art { "path": "Bracket.3d.tsx", "view": "front", "format": "ansi" }

The tool and this page use the same module: the CommandAGI host carries it, and this site carries a copy of the same file.
